# Тон-маппинг и цветокоррекция

В данном задании вам предстоит развить навыки GPGPU-программирования, познакомиться с основами теории цвета и добавить в рендерер тон-маппинг и цветокоррекцию.

## Перед началом

1. Используйте решение предыдущих заданий, включающее отложенное освещение и процедурное небо.
2. По возможности прочитайте [краткое объяснение](https://computergraphics.stackexchange.com/a/10318) того, что такое цветовые пространства, гамма-коррекция и тон-маппинг.

## Задание

#### Шаг 1

Поменяйте ваш рендерер, чтобы он:

1. Использовал картинку формата `B10G11R11_UFLOAT` при рендеринге.
2. Переносил содержимое этой картинки в `R8G8B8`-бэкбуфер при помощи пиксельного шейдера, просто квантующего диапазон [0, 1] на 256 значений и ограничивающего значения больше 1 (нужно ли вообще писать какой-то код, чтобы получить такое поведение в шейдере?).

В данном контексте картинку формата `B10G11R11_UFLOAT` будем называть HDR-изображением (high dynamic range), бэкбуфер — LDR-изображением (low dynamic range), а шейдер, переносящий его содержимое в бэкбуфер, — шейдером постобработки.

#### Шаг 2

Добавьте в шейдер постобработки «наивный» тон-маппинг.

Вычислите по HDR-изображению его экспозицию и используйте её, чтобы при переходе в LDR-изображение потерять как можно меньше точности на текущем кадре.

Для этого:

1. Напишите compute shader, который посчитает минимум и максимум уровней освещённости в исходном изображении.
2. Напишите compute shader, который посчитает гистограмму плотности распределения логарифмов (почему?) уровней освещённости пикселей HDR-изображения с примерно 100 уровнями квантования, распределёнными равномерно от минимума до максимума.
3. Выберите на основе гистограммы экспозицию для текущего кадра (как: медиана, среднее, квантиль?).
4. Модифицируйте шейдер постобработки, чтобы он использовал экспозицию при переводе изображения в LDR.
5. Придумайте, как сделать, чтобы тон-маппинг был не так чувствителен к малейшему изменению угла камеры и не вызывал резких скачков яркости.

За использование `shared memory` для накопления локальных результатов в рамках группы потоков полагаются дополнительные баллы. Однако лучше реализовать оба варианта и сравнить их производительность в профилировщике.

Подумайте, что здесь имеется в виду под яркостью. Есть ли у яркости понятное представление в цветовой модели RGB? А в других цветовых моделях?

Нужно ли менять значение `auto-gamma` при инициализации Etna?

Добавьте в ImGui возможность включать и выключать тон-маппинг для сравнения результатов.

#### Шаг 3

Реализуйте цветокоррекцию с использованием трёхмерной таблицы преобразования цветов (*3D LUT*) размером 32×32×32.

Для создания LUT возьмите исходное изображение и его версию после цветокоррекции в графическом редакторе. Постройте таблицу соответствия исходных RGB-цветов изменённым:

1. Разбейте пространство RGB на ячейки размером 32×32×32.
2. Для каждого пикселя исходного изображения определите ячейку по его цвету.
3. Усредните цвета соответствующих пикселей обработанного изображения внутри каждой ячейки.
4. Для ячеек, в которые не попали пиксели, используйте цвет ближайшей заполненной ячейки.

Сохраните результат в трёхмерную текстуру `R8G8B8A8_UNORM`.

В шейдере постобработки используйте полученный после тон-маппинга и гамма-коррекции цвет как координаты для выборки из `sampler3D`. Настройте линейную фильтрацию, чтобы переходы между цветами были плавными.

Добавьте в ImGui возможность **независимо включать и выключать тон-маппинг и цветокоррекцию**.
